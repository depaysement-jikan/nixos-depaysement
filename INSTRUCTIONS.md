# NixOS & Home Manager Configuration Guide

This guide provides the necessary steps to get this configuration up and running on a new machine. The configuration relies heavily on **Flakes**, **Disko**, and **sops-nix** for secret management.

---

## 📋 Requirements

1.  **NixOS Installation Media**: A USB drive with the NixOS installer.
2.  **Internet Connection**: Required for fetching flake inputs and packages.
3.  **SSH Access**: To manage secrets and potentially install remotely via `nixos-anywhere`.
4.  **Hardware Awareness**: Each host has its own hardware and disk layout. The existing hosts are:

    | Host        | User          | Shell   | Disk target    | Display manager |
    | ----------- | ------------- | ------- | -------------- | --------------- |
    | `shinobu`   | `kokoro`      | nushell | `/dev/nvme0n1` | tuigreet        |
    | `tsukinara` | `depaysement` | nushell | `/dev/nvme0n1` | SDDM            |
    | `yotsugi`   | `yay`         | zsh     | `/dev/nvme0n1` | tuigreet        |
    | `sodachi`   | `riddle`      | zsh     | `/dev/sda`     | SDDM            |

    Throughout this guide, replace `<HOST>` and `<USER>` with the pair you are installing.

## 🚀 Installation Steps

### 1. Copy paste your own hardware-configuration.nix

The hardware configuration file is auto-generated by NixOS, and its custom fit for your own system, so if you are installing this config, you will need to bring your own hardware configuration. Simply look for `hosts/<HOST>/hardware-configuration.nix` and replace its contents with your own (generate it with `nixos-generate-config`).

### 2. Declare the host

Hosts and their users are declared centrally in [`nixos/configuration.nix`](nixos/configuration.nix); the
flake generates `nixosConfigurations.<HOST>` and `homeConfigurations.<USER>@<HOST>` from that file. If you
are adding a machine, add an entry there:

```nix
<HOST> = {
  system = "x86_64-linux";
  profile = "desktop";      # or "server"
  platform = "nixos";
  users = {
    <USER> = {
      root.enable = true;
      shell = "nushell";    # bash | zsh | fish | nushell
    };
  };
};
```

The schema for these options lives in [`nixos/utils/options.nix`](nixos/utils/options.nix).

### 3. Apply the disk layout

If you are performing a fresh installation, you can use **Disko** to automatically partition your drives.

> [!CAUTION]
> Each host's disko file targets a specific device (see the table above). Ensure it matches your hardware before proceeding.
> Disko is imported only when `hosts/<HOST>/disko/` exists, so for an existing installation simply delete that directory rather than editing `flake.nix`.

```bash
sudo nix --experimental-features "nix-command flakes pipe-operators" run github:nix-community/disko -- --mode disko ./hosts/<HOST>/disko/default.nix
```

### 4. Configure Host Options

Before building, review and adjust the host-specific and user-specific options. You can toggle features, applications, and desktop environments here.

- **NixOS Global Config**: `hosts/<HOST>/config/nixos-config/default.nix`
- **Home Manager Config**: `hosts/<HOST>/users/<USER>/config/home-manager-config/default.nix`
- **Homelab Config**: `hosts/<HOST>/config/homelab-config/default.nix`

See [modules/nixos/README.md](modules/nixos/README.md) and
[modules/home-manager/README.md](modules/home-manager/README.md) for the full option trees.

### 5. Secrets Management (sops-nix)

#### Steps

To get `sops-nix` working and manage your secrets:

1.  **Ensure `sops` and `age` are installed:**
    Make sure `pkgs.sops` and `pkgs.age` are included in your modules.

2.  **Generate an AGE private key (if you don't have one):**
    This key is crucial for decrypting your secrets. Store it securely and _do not_ commit it to Git.

    ```bash
    mkdir -p /var/lib/sops-nix/age
    age-keygen -o /var/lib/sops-nix/age/keys.txt
    ```

    **Important:** Back up this `keys.txt` file immediately! Losing it means permanent loss of access to your encrypted secrets.

3.  **Get your AGE public key:**
    You'll use this public key to encrypt your `secrets.yaml` file.

    ```bash
    age-keygen -y /var/lib/sops-nix/age/keys.txt
    ```

    Copy the output (a string starting with `age1...`). This is your public key.

4.  **Get your SSH key:**
    You will also need an ssh key that will be registered with sops

    ```bash
    sudo ssh-keygen -t ed25519 -f /var/lib/sops-nix/.ssh/<HOST> -N <HOST>
    ```

5.  **Create or encrypt your `secrets.yaml` file:**
    If you have an existing plain-text `secrets.yaml` (e.g., at `hosts/<HOST>/users/<USER>/secrets.yaml`), you can encrypt it in-place. If you're creating it from scratch, you can provide the content directly.
    - **Encrypting an existing plain-text `secrets.yaml` in-place:**
      Ensure your `secrets.yaml` file contains the plain-text secrets you wish to encrypt. For example:

      ```yaml
      hashedPassword: your user password hashed using `mkpasswd -m sha-512 "password"`
      userGitName: your GIT name
      userGitEmail: your_email@example.com
      userPublicSshKey: contents of your ssh pub key
      ```

      Then run the encryption command:

      ```bash
      sops --encrypt --age <YOUR_AGE_PUBLIC_KEY> --in-place hosts/<HOST>/users/<USER>/secrets.yaml
      ```

      Repeat for any other secret files. Beyond the per-user file, the homelab keeps its own at
      `modules/homelab/secrets.yaml`, `pihole-secrets.yaml`, `cert-secrets.yaml` and
      `tailscale-secrets.yaml` — these only matter if you enable the homelab.

6.  **Run NixOS Rebuild:**
    After your `secrets.yaml` is correctly encrypted and your keys are in place, apply your NixOS configuration:
    ```bash
    sudo nixos-rebuild switch --flake .#<HOST>
    ```
    This will activate the `sops-nix` service, which will decrypt and manage your secrets.

> [!TIP]
> Once you have rebuilt at least once, `resetSopsSecrets` walks you through re-entering and re-encrypting
> any of these files interactively.

> [!CAUTION]
> If you are going to be posting this on your own repo, please remove the .github/workflows/mirror-config.yaml workflow as that mirrors any commits into a mirror, which you would lack credentials for, which will cause a pipeline error.

## 🛠️ Deployment

### 1. Apply NixOS Configuration

Rebuild the system using your host's flake output:

```bash
sudo nixos-rebuild switch --flake .#<HOST>
```

Once `nh` is installed (it is enabled for every user here), the shorter form is:

```bash
nh os switch .#<HOST>
```

### 2. Apply Home Manager Configuration

Home Manager runs as a NixOS module, so the command above already builds the user environment. To rebuild
only the user environment, use the standalone output:

```bash
home-manager switch --flake .#<USER>@<HOST>
# or
nh home switch .#<USER>@<HOST>
```

### 3. Optional: Setup NVIM

This config does not currently offer a nixvim config, but please feel free to follow the steps on [INSTRUCTIONS-NVIM.md](/INSTRUCTIONS-NVIM.md) for regular non NixOS setup.

## 🔄 Maintenance & Updates

- **Update Flake Inputs**:
  ```bash
  nix flake update
  ```
- **Validate the flake** (the same check CI runs):
  ```bash
  nix flake check
  ```
- **Format Nix files** (the flake's formatter is `alejandra`):
  ```bash
  nix fmt
  ```
- **Garbage Collection**:
  ```bash
  sudo nix-collect-garbage -d
  ```

## ⚠️ Troubleshooting

- **Sops Failures**: Ensure your age key matches the one used to encrypt the files. If you lose your private key, you will need to re-generate the secrets.
- **Hardware Config**: If installing on different hardware, regenerate `hosts/<HOST>/hardware-configuration.nix` using `nixos-generate-config`.
- **Missing Secrets**: If a build fails with a "file not found" error related to sops, ensure all required `.yaml` files mentioned above exist (even if empty).
- **Experimental features**: This flake uses `pipe-operators` in addition to `nix-command` and `flakes`. If you evaluate it from a machine that is not yet running this configuration, pass all three via `--experimental-features`.
- **Boot or desktop failures after an update**: the [`diagnostics-and-guides/`](diagnostics-and-guides)
  directory has write-ups for a black screen after moving to unstable, an ext4 root corruption recovery, and
  an ongoing investigation into random freezes.
